# Viggo's Barbershop: specification

This page holds the owner's decisions in force (D) and the rules the November 2026 fix plan adds (R). Each row names the test that enforces it. **now** means that test exists and runs in `npm test`, which the Netlify build runs before every deploy. **step N** means plan step N adds the enforcement; a planned file name may change, and the step that adds the test updates its row and sets it to **now**. A decision changes only with the owner, and the page, the test and the code change in the same commit. `test/docs/spec.test.mjs` checks this page.

**Privacy facts (D6).** These are the only facts `personvern.html` may state.

- **Controller:** Viggos Barbershop Kurti, org.nr 937 845 812, Violgata 22, 1776 Halden, phone 409 63 911, kurtivigan1@gmail.com.
- **Data:** name, phone number, and the chosen service, add-ons and time.
- **Purpose:** the booking, plus the barber's notifications and calendar.
- **Legal basis:** GDPR art. 6(1)(b).
- **Processors and recipients:** Netlify for hosting, functions and storage (Netlify Blobs; Netlify, Inc., USA), the only booking store. The barber's notification (name, service and time, never the phone number) travels encrypted through his browser's push service: Apple, Google, Mozilla or Microsoft. If the barber subscribes his phone calendar, his calendar service (iCloud or Google Calendar) fetches name, phone, service and time. Google: the map (loaded only after a click) and, when the reviews section shows Google data, the reviewers' photos; the reviews themselves are fetched server-side. Instagram (Meta): post images, only when the feed has posts. The fonts are self-hosted since step 6 (F47), so Google no longer serves fonts; this replaces the earlier "Google for fonts".
- **Abuse counters:** web bookings per IP address, per phone and in total, and logins per IP address and in total. Each hit stores its time and an id for the attempt (for a web booking a keyed hash of its requestId, date, time and phone, so a hit can be linked to its booking while both exist); a per-address or per-phone hit also stores the keyed hash of the IP address or phone, never the value itself, and the shared booking counter when the cap last alerted the barber. The documents are a fixed set whatever the traffic (R44). Every hit is removed by the first daily clean-up after it is 24 hours old, so at the latest 48 hours after the attempt.
- **Visitor statistics:** per Oslo day, page views per page (front page, personvern), visits (views not reached from another page of the site) and the source group of each visit (Instagram, Facebook, Google, TikTok, direct, other). Once the day is 14 days old, the number of bookings made that day is added: from the website or /admin, cancelled, per service and per weekday; numbers only, no name, phone or other customer data. No cookies, no IP address, no ID, no browser data, no referrer address; nothing is stored on the visitor's device. Only the published site counts; bots and previews are skipped. Kept 400 days, at Netlify (functions and Blobs).
- **On the device:** only the visitor's own language choice (localStorage `lang`), when English is chosen.
- **Retention:** bookings are deleted 90 days after the appointment (by the daily clean-up, so at the latest 91 days after the appointment date). Every period stated on the page is its worst case: the threshold plus one clean-up interval (R30).
- **Rights:** the visitor's GDPR rights, including the right to complain to Datatilsynet.

**Art. 13 checklist (fix-up round 2).** Each item of GDPR art. 13(1)(a)–(f) and 13(2)(a)–(f) is either said on `personvern.html` (`test/page/privacy.test.mjs` holds the sentence for each) or has a row here: «not applicable, because …», or «open: …» with the DEPLOY §6 line that keeps it from being published unanswered.

- **Art. 13(1)(b)** not applicable, because there is no data protection officer: a one-person barbershop whose core activities are neither large-scale monitoring nor special categories of data (art. 37) is not required to have one.
- **Art. 13(1)(d)** not applicable, because the page names only art. 6(1)(b); if the owner adds art. 6(1)(f) for the abuse counters (DEPLOY §6), the page must name the legitimate interest.
- **Art. 13(1)(f)** open: Netlify, Inc. is in the USA, and the page names no transfer basis. The mechanism (Netlify's data processing agreement: EU–US Data Privacy Framework certification or standard contractual clauses) has not been verified, so the page does not state one; DEPLOY §6 «Overføring til USA» asks for it to be checked and added before publishing.
- **Art. 13(2)(c)** not applicable, because nothing is based on consent (art. 6(1)(a)).
- **Art. 13(2)(f)** not applicable, because there is no automated decision-making or profiling.
