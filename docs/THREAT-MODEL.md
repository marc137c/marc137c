# Threat model: the server endpoints

One row per way in. **Who** is who can call it. **Rate** is how often it is called in normal use. **Cost** is the Blobs work per call. **Limit** is what stops abuse. **Test** names the file that holds the limit in place. Every endpoint below answers 410 `Bruk hovedsiden.` on a retired deploy before it opens a store; `/api/availability` is the exception, since it reads and never writes. The rules behind that are in `docs/contracts/netlify.md`.

| Endpoint | Who | Rate | Inputs | Cost | Limit | Test |
|---|---|---|---|---|---|---|
| `POST /api/bookings` | anyone (the booking form) | a few per day | JSON ≤ 4000 chars: service, date, start, name ≤ 80, phone ≤ 30 chars and 8-15 digits, add-ons (each once), optional `requestId` | 3 counter writes + 1 month write + push | same-site JSON only (415/403); per client 5/h and 10/24 h (IPv6 per /64); per phone 6/24 h; all web bookings 20/h and 40/24 h. Every counter is checked before any is written, a refused or taken attempt is refunded, and the barber gets one push when the global cap trips. A `requestId` retry stores and counts once. | `test/functions/rate-limit.test.mjs`, `test/functions/bookings.test.mjs`, `test/functions/validators.test.mjs`, `test/functions/fault-matrix.test.mjs` |
| `GET /api/availability` | anyone | every page view with the form | none | reads 2-3 month docs | returns only busy ranges, closed dates and the config, never names or phones | `test/functions/availability.test.mjs` |
| `POST /api/admin/login` | anyone, really the barber | a few per month | password, `remember`, `device` mark | 1-2 counter writes | each attempt is counted before the password check: 10 per 15 min per client, 100 per 15 min in total. A device mark from an earlier login skips the total, so a guesser cannot lock the barber out. A wrong password waits 500 ms. Tokens are signed with a scrypt-derived key. | `test/functions/admin.test.mjs`, `test/lib/auth-keys.test.mjs` |
| `/api/admin/items`, `/api/admin/items/:id` | the barber (token) | tens per day | JSON ≤ 20000 chars; PATCH may carry `expect` | 1-2 month writes | token required, and a token issued before `auth/epoch` is refused. A stale `expect` gets 412. Every write is conditional, a cross-month move keeps its id, and a half-done move answers 503. | `test/functions/admin.test.mjs`, `test/functions/fault-matrix.test.mjs` |
| `POST /api/admin/cancel-phone` | the barber (token) | after a flood | `phone` (8-15 digits) | up to 4 month writes | token required; cancels only web bookings from today on; idempotent | `test/functions/admin-cancel-phone.test.mjs` |
| `/api/admin/push*`, `/api/admin/calendar` | the barber (token) | on login and in Oppsett | subscription JSON ≤ 4000 chars | 1 write | token required. Only known push services are accepted. Devices are tied to the password and to the login's expiry, and an expired device gets one notice with no customer data. Reset ends every other login. | `test/functions/admin-push*.test.mjs`, `test/functions/admin-calendar.test.mjs` |
| `GET /api/calendar/<secret>.ics` | the barber's calendar app | every 15 min | a 256-bit secret in the path | reads the feed doc and about 14 months | a wrong secret gets the same 404 and reads no booking. Never cached; stops after a password change. | `test/functions/calendar-feed.test.mjs` |
| `GET /api/bookings/<id>.ics` | the customer who booked | once per booking | a booking id (date + 40 random bits) | reads 1 month doc | only a not-cancelled web booking. Holds no name or phone, so guessing ids reveals only that a slot is taken, which `/api/availability` shows anyway. | `test/functions/booking-ics.test.mjs` |
| `POST /api/push/renew` | the barber's service worker | rarely | old endpoint plus its auth secret, new subscription | 1 write | same-site JSON only; replaces only a stored device whose auth secret matches | `test/functions/push-renew.test.mjs` |
| `POST /api/hit` | every page view | per visit | JSON ≤ 1 kB: path and referrer host | 1 day-doc write | counts only on the live, published production deploy; skips bots, an empty user agent and cross-site posts. Stores counts only, with no IP, ID or cookie. An inflated count is the worst case. | `test/functions/stats.test.mjs` |
| `GET /api/stats` | the barber (token) | when the panel opens | none | reads 30 day docs | token required, with `auth/epoch` | `test/functions/stats.test.mjs` |
| retention (daily schedule) | Netlify's scheduler | daily | none | lists and edits every doc | runs only on the published deploy (a call without deploy information counts as that one), does nothing on a retired one, and cleans only preview stores under another named context such as `dev`. Deletes a counter only if its ETag is unchanged. | `test/functions/retention.test.mjs`, `test/functions/store-keys.test.mjs` |

**Deploy previews and branch deploys.** These are public URLs running branch code. They use their own stores (`bookings-preview`, `stats-preview`), so a test booking or a guessed login there never touches the live timebook. Their statistics are not counted. Test: `test/functions/deploy-context.test.mjs`.

**Old permalinks.** An older production deploy keeps its code and its `ADMIN_PASSWORD` at `<deploy-id>--<site>.netlify.app`. Every endpoint that writes or shows the booking store answers 410 there, the login included. After each publish, delete the older deploys. Test: `test/functions/deploy-context.test.mjs`.

**Store contents.** Every key the server writes, what it holds and when it is deleted are listed in `netlify/lib/store-keys.mjs`. No key name contains a phone number or an IP address. Every `setJSON` is conditional, or says why it is not. Tests: `test/functions/store-keys.test.mjs`, `test/scripts/blind-writes.test.mjs`.

**Not covered here (step 5).** `/api/reviews`, `/api/social` and `/api/connect/instagram` still write blindly, and their Google and Instagram contracts are covered in step 5.
